# 公开 UC 实例首次分支诊断

## 1. 实验目的

本实验不比较哪一种分支规则更好，只回答一个前置问题：SCIP 需要等待多久，才能完成根节点工作并第一次要求选择分支变量。

运行到第一次分支时立即停止，不选择变量，也不继续搜索。因此，下表时间不是求解完整 UC 的时间。

## 2. 实验对象与配置

选取五个 24 小时、500 台以下公开实例：

- OR-LIB 200 台：`or-lib_200_0_1_w`、`or-lib_200_0_12_w`；
- Tejada19：214、290、480 台。

每个实例运行三种配置，全部使用单线程、固定随机种子和 300 秒上限：

1. `official_default`：UnitCommitment.jl v0.3 官方 MPS，SCIP 默认根节点设置；
2. `official_root_lite`：同一官方 MPS，禁止预处理重启，根节点最多一轮分离、最多 100 个割，并使用 SCIP 的 FAST 启发式设置；
3. `compact_root_lite`：项目的紧凑 `ucjl03` 模型，使用相同的根节点轻量设置。

轻量配置没有删除 UC 的负荷、备用、爬坡、最小开停机时间和启停逻辑。紧凑模型使用较少的辅助变量和强化约束表达；它服务于分支研究，官方 MPS 仍是最终性能验证模型。

## 3. 首次分支时间

| 实例 | 官方默认 | 官方轻量 | 紧凑轻量 | 官方轻量相对默认 |
|---|---:|---:|---:|---:|
| OR-LIB 200-1 | 211.10 秒 | 77.10 秒 | 78.27 秒 | 2.74 倍快 |
| OR-LIB 200-12 | 173.56 秒 | 60.17 秒 | 57.85 秒 | 2.88 倍快 |
| Tejada19 214 | 36.64 秒 | 24.16 秒 | 12.39 秒 | 1.52 倍快 |
| Tejada19 290 | 50.89 秒 | 26.57 秒 | 18.58 秒 | 1.92 倍快 |
| Tejada19 480 | 96.58 秒 | 77.60 秒 | 40.34 秒 | 1.24 倍快 |

三种配置在全部五个实例上都于 300 秒内到达首次分支。五个实例的统计量为：

| 配置 | 平均时间 | 中位时间 | 最慢时间 |
|---|---:|---:|---:|
| 官方默认 | 113.75 秒 | 96.58 秒 | 211.10 秒 |
| 官方轻量 | 53.12 秒 | 60.17 秒 | 77.60 秒 |
| 紧凑轻量 | 41.49 秒 | 40.34 秒 | 78.27 秒 |

## 4. 为什么以前会看到“60 秒内不分支”

60 秒上限把两种时间混在了一起：

1. 完成预处理、根节点 LP、割和启发式所需的准备时间；
2. 真正由 RPB 或公开评分程序控制的分支搜索时间。

例如，OR-LIB 200-1 使用官方默认配置要约 211 秒才第一次分支，所以原来的 60 秒实验不可能评价任何分支规则。Tejada19 290 即使能在 60 秒内分支，也只剩约 9 秒供默认配置搜索。

## 5. 模型规模与计算量证据

紧凑模型确实减少了约束数量：

| 实例 | 官方变量/约束 | 紧凑变量/约束 |
|---|---:|---:|
| OR-LIB 200-1 | 48,072 / 86,292 | 43,200 / 62,414 |
| OR-LIB 200-12 | 48,072 / 95,870 | 43,200 / 62,378 |
| Tejada19 214 | 51,432 / 98,748 | 46,224 / 66,641 |
| Tejada19 290 | 69,672 / 134,838 | 62,640 / 90,245 |
| Tejada19 480 | 115,272 / 222,902 | 103,680 / 149,368 |

根节点轻量配置也明显减少了到首次分支前的 LP 迭代。例如：

- OR-LIB 200-1：277,634 次降至 137,325 次；
- OR-LIB 200-12：267,482 次降至 136,038 次；
- Tejada19 290：66,410 次降至 32,224 次。

因此，加速不是简单隐藏日志或改变计时，而是确实减少了首次分支前的求解工作。

## 6. 对后续分支研究的决定

### 主结果：官方模型

正式比较 RPB、公开程序和后续 UC 程序时，优先使用 `official_root_lite`。这保留官方 UnitCommitment.jl 模型，同时把平均首次分支时间从 113.75 秒降到 53.12 秒。

计时应拆成两段：

- `root preparation time`：从开始求解到第一次分支；
- `branch search budget`：从第一次分支开始，为每种分支规则再提供完全相同的时间或决策次数。

不能再使用“从读取模型开始统一 60 秒”评价分支规则，因为不同实例的有效分支时间差异过大。

### 训练与快速迭代：紧凑模型

使用 `compact_root_lite` 收集候选变量、特征和强分支标签。它在 Tejada19 214/290/480 上分别于约 12/19/40 秒开始分支，适合频繁重复实验。

紧凑模型上的优秀程序必须回到官方模型复验。两种模型的根节点松弛不同，不能只报告紧凑模型结果。

### 实例分层

- 快速主训练池：Tejada19 214、290；
- 大规模训练/验证：Tejada19 480；
- OR-LIB：采用官方轻量配置并允许约 80 秒根节点准备，或用紧凑模型训练；
- 官方默认设置：保留为最终端到端求解基准，不用于给分支策略分配固定 60 秒预算。

## 7. 结果位置与复现

- 汇总结果：`outputs/public_branching/first_branch_diagnostic/summary.json`
- 每组独立结果：同目录下的实例子目录；
- 可恢复运行脚本：`scripts/diagnose_first_branch.py`
- 诊断实现：`src/ucbranch/root_diagnostics.py`

复现命令：

```bash
.conda/llm4branch/bin/python scripts/diagnose_first_branch.py \
  --limit 300 \
  --output outputs/public_branching/first_branch_diagnostic
```

已有结果会自动跳过，不会重复消耗计算时间。

## 8. 适用范围与限制

- 当前每个“实例×配置”只运行一次，足以做可行性筛选，但正式论文应使用多个随机种子或重复运行报告波动；
- 当前停止在第一次分支，不能据此判断最终求解时间一定改善；
- 不同配置的首次候选数不同，因为根节点割和松弛解发生了变化；
- 紧凑模型与官方强化模型具有不同的连续松弛，训练迁移效果必须通过后续实验验证。
