# 公开 UC 数据与首轮分支实验执行记录

## 1. 现在研究的到底是什么

当前问题固定为：单母线、纯火电机组、24 个一小时时段，考虑负荷平衡、
旋转备用、最大/最小出力、最小开停机时间、爬坡、启动和停机限制，以及
分段线性发电费用。暂时不加入输电网络、风光不确定性和储能，避免同时改变
太多因素后无法判断改进来自哪里。

## 2. 数据已经怎样冻结

28 个原始压缩 JSON 均来自 UnitCommitment.jl v0.3 公共实例库，没有改写。
每个文件的 SHA-256 指纹和唯一分组记录在
[`configs/public_uc_splits.json`](../configs/public_uc_splits.json)：

| 用途 | 实例 | 数量 |
|---|---|---:|
| 训练 | OR-LIB 200 系列 1–8 | 8 |
| 验证 | OR-LIB 200 系列 9–10 | 2 |
| 同规模测试 | OR-LIB 200 系列 11–12 | 2 |
| 大规模测试 | Tejada19 214、250、290、480、505、623、647 | 7 |
| OOD（超出训练规模） | Tejada19 836、850、918、931、940、957、959、1069、1130 | 9 |

OOD 可以理解为“考试题明显比练习题大”。这组数据专门检查在 200 台附近学到
的分支规律，到了 800–1130 台时是否仍然有效。

## 3. 为什么模型有 `standard` 和 `ucjl03` 两种口径

对账发现 UnitCommitment.jl v0.3 默认模型的强化爬坡公式，比它自带的公开
可行性检查器更严格。两者代表两种规则口径：

- `standard`：按常见物理含义检查实际发电量的启动、停机和爬坡；
- `ucjl03`：复现 UnitCommitment.jl v0.3 默认模型对“超过最低出力部分”的
  强化限制。

后续与官方结果及分支规则比较时统一使用 `ucjl03`。`standard` 留作解释物理
规则和排查差异，不能把两种口径的数值混在同一张性能表里。

## 4. 官方模型对账结果

对账不是只比较两个目标值，而是双向进行：官方模型的解固定到我们的模型中，
我们的解也交给官方独立检查器。结果如下。

| 实例 | 官方目标值 | 我们的目标值 | 结论 |
|---|---:|---:|---|
| OR-LIB `200_0_1_w` | 35,875,463.302801（60 秒可行解） | 固定同一开停机方案后 35,875,463.302801 | 一致；该次官方求解尚有 2.00% gap |
| Tejada19 `214g` | 3,250,183.600388 | 3,250,183.600388 | 双方均求到最优，官方检查器接受我们的解 |

这里的 gap 是“当前最好可行方案与理论下界之间还剩多少距离”。OR-LIB 的
60 秒结果不是最优答案，因此不能用两套求解器在 60 秒时各自找到的可行解是否
相同来判断模型是否相同；固定同一方案后费用与可行性一致才是有效核对。

## 5. 六种方法的第一轮 214×24 接口试跑

每种方法单线程、固定随机种子，最长 30 秒。这里只是一张接口和趋势检查表，
不是最终统计结论。

这张旧表使用项目自行建立的 `ucjl03` 整数等价模型。随后已经完成官方默认
模型直接导出 MPS 的 500 台以下实验；正式分析应以
[500 台以下官方 MPS 自适应实验](UNDER500_OFFICIAL_MPS_RESULTS_ZH.md)为准。

| 方法 | 口径 | 状态 | 节点 | 最终 gap | 外部选变量次数 |
|---|---|---|---:|---:|---:|
| 默认 SCIP | 完整默认求解流程 | 18.55 秒最优 | 79 | 0 | 0 |
| RPB | LLM4Branch 控制设置 | 到时停止 | 33 | 1.87e-7 | 0（SCIP 内部选择） |
| setcover 程序 | LLM4Branch 控制设置 | 到时停止 | 58 | 6.03e-7 | 57 |
| cauctions 程序 | LLM4Branch 控制设置 | 到时停止 | 60 | 6.28e-7 | 59 |
| facilities 程序 | LLM4Branch 控制设置 | 到时停止 | 62 | 5.93e-7 | 57 |
| indset 程序 | LLM4Branch 控制设置 | 到时停止 | 56 | 6.61e-7 | 54 |

四份程序均为上游仓库原文件，未针对 UC 改写。它们实际选择过 `u`（开机）、
`y`（启动）和 `z`（停机）三类变量，说明通用的 91 维特征接口可以在完整 UC
模型上工作。

默认 SCIP 保留了割平面等完整工具；RPB 和四份程序则按 LLM4Branch 论文的
受控设置关闭部分工具，以便突出“选哪个变量分支”的影响。因此默认 SCIP 是
实用基准，RPB 才是四份程序的直接公平基准。不能仅按上表节点数宣布某程序
优于默认 SCIP。

## 6. 如何复现

```bash
# 我们的 ucjl03 模型
PYTHONPATH=src .conda/llm4branch/bin/python scripts/public_uc.py \
  data/public_uc/tejada19_UC_24h_214g.json.gz --formulation ucjl03 --limit 60

# 官方 MPS 自适应分支实验
PYTHONPATH=src .conda/llm4branch/bin/python scripts/adaptive_public_branching.py \
  --limit 60 --mps-dir outputs/public_uc_mps

# 官方 Julia 参考环境（需要本机已有 Julia 1.10）
julia --project=reference/unitcommitment -e 'using Pkg; Pkg.instantiate()'
julia --project=reference/unitcommitment reference/unitcommitment/solve.jl \
  data/public_uc/tejada19_UC_24h_214g.json.gz solution.json metrics.json 60
```

## 7. 下一步怎样避免再次钻进死胡同

下一阶段不立即训练 LLM。先对冻结列表批量运行六种方法，并同时记录目标值、
下界、gap、节点、LP 迭代和墙钟时间。先确认哪些规模真的会产生足够多的分支
决策，再只用训练组生成扰动样本；验证、测试和 OOD 文件保持不动。最终结论要
跨多个实例汇总，而不是依据这一个 214 台样例。
