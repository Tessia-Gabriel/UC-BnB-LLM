# 公开 UC 数据、SCIP 与 LLM4Branch 公开程序

## 三个东西分别是什么

**公开 UC 实例**是一份公开的考试卷，里面写着每台机组的能力和成本、24 小时需求、
初始开关状态、备用要求等。它不是算法。项目现已保存 OR-LIB 200 台实例和
Tejada19 505 台实例，原始压缩 JSON、来源、许可证和 SHA-256 均保留在
`data/public_uc/`。

**SCIP**是真正解题的通用优化软件。它负责寻找合法发电计划，并用数学方法判断
是否还能存在更便宜的计划。所谓“默认 SCIP”，就是不替换它选择分支问题的规则。

**LLM4Branch 公开程序**是作者经过搜索后公开的四段短 Python 评分代码。
每段代码读取候选变量的情况表，给候选打分，帮助 SCIP 决定先对哪个整数变量拆题。
它们分别来自 set covering、combinatorial auction、facility location 和
independent set 实验。它们不是 UC 数据、不是完整求解器，也不在求解时调用 LLM。

“四份程序逐一与默认 SCIP 比较”的意思是，对完全相同的公开 UC 试卷和时间预算，
分别运行 SCIP 自带规则，以及四段公开评分代码。比较完成率、时间和剩余 gap。
正式实验还要增加 LLM4Branch 论文的直接基线 RPB（relative pseudocost branching）。
也就是说需要两个参照：原生 SCIP 回答“实际有没有价值”，RPB 回答“是否公平复现
作者仅替换变量选择规则的实验”。不能把 RPB 简写成完整的默认 SCIP。
这一步尚未执行；之前名为 `llm4branch` 的结果只用了我们自己的两特征简化程序，
不能代表这四份作者公开程序。

## 特征维数与复用状态

锁定版本提供 **91 维**候选变量特征，编号 0 到 90：前 19 维来自
NodeBipartite，后 72 维来自 Khalil2016。某些其他代码或文章出现 92 维时，
必须先核对具体版本和定义；不能在本项目中直接多算一维。

我们已经复用了上游的特征提取器和 normalize，但此前固定程序只用了第 9、43 维，
没有充分复用作者公开的规则。下一条基线应直接加载四份原程序；程序自己声明使用
哪些维度，上游定制 Ecole 只计算所需维度，以控制大规模上的开销。

四份规则使用的是同一套通用特征，但公式和参数来自各自原问题。论文报告了跨问题
迁移实验，说明直接迁移值得先试；结果并非每个来源规则在每个目标问题上都更好，
所以它们是必须测试的现成候选，而不是已知适用于 UC 的答案。

公开规则可以直接给普通整数变量打分。它们不能未经定义就给“多个变量之和”这种
结构对象打分；这是未来结构扩展需要解决的问题，不应挡住当前变量规则复现。

## 公开 UC 接入到了什么程度

`src/ucbranch/public_uc.py` 目前严格读取 UnitCommitment.jl v0.3 的单母线子集，保留：

- 24 小时负荷和旋转备用；
- 初始开停状态与初始出力；
- 分段线性发电成本；
- 最小开停时间、爬坡限制、启动成本；
- 机组能否提供备用。

遇到网络线路、多个母线、多个备用产品、多档启动成本等未实现内容会报错，
不会静默删除。200 台和 505 台数据的读取、模型构建测试已通过。

这里必须保留一个边界：当前 PySCIPOpt 模型是我们根据公开字段实现的参考模型，
还没有与 UnitCommitment.jl 官方默认模型逐项核对目标值，所以目前可以说“公开数据已接入”，
不能说“已经完整复现 UnitCommitment.jl”。正式比较公开规则之前需要完成这一核对。
