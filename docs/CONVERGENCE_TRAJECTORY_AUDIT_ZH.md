# 分支策略收敛速度实验审计

## 1. 最终采用的主指标

本轮不再以 60 秒结束时的单个 gap 作为主要指标，而使用：

> **首次分支后 60 秒内，`gap(t) / gap(0)` 曲线的平均面积。**

报告字段为 `mean_gap_ratio`，数值越小表示收敛越快：

- 接近 1：60 秒的大部分时间里几乎没有改善；
- 接近 0：很早就把 gap 降到接近 0；
- 等于 0：从一开始就是最优状态。

之所以除以第一次分支时的 `gap(0)`，是因为 RPB 与外部 Ecole 程序到达第一次分支时的初始 gap 并不完全相同。直接比较绝对 Gap 面积会把根节点起点差异混入分支速度。

辅助指标包括：

- gap 降到初始值的 90%、50%、10%、1%所需时间；
- 达到 RPB 在 60 秒时水平所需时间；
- 60 秒时的 gap；
- 证明最优的时间；
- 节点数和 LP 迭代数，仅用于解释。

## 2. 完整性与预算审计

| 检查项 | 结果 |
|---|---|
| 实例 | 5 个代表实例 |
| 方法 | 6 种 |
| 运行数 | 30/30 完成 |
| 独立结果文件 | 30/30 |
| 输入 MPS 哈希 | 全部一致 |
| 到达首次分支 | 30/30 |
| 具有可行解 | 30/30 |
| 轨迹时间是否单调 | 全部通过 |
| 轨迹点数量 | 共 7,016 个，每组 12 至 571 个 |
| 非最优运行墙钟时间 | 60.011 至 60.364 秒 |
| 累计墙钟时间 | 53.69 分钟 |

边界最多超过 60 秒约 0.364 秒，原因是外部程序已经进入一次分支评分或 SCIP 调用，不能在调用中间强制中断。所有积分、阈值时间和 `gap_at_horizon` 已严格截断在 60 秒；超过 60 秒的状态不计入主指标。

## 3. 所有方法的归一化收敛面积

数值越小越好。粗体为每个实例最快的方法。

| 实例 | SCIP默认 | RPB | setcover | cauctions | facilities | indset |
|---|---:|---:|---:|---:|---:|---:|
| OR-LIB 200-1 | 0.994951 | 0.994944 | 0.933367 | 0.861041 | 0.856779 | **0.800859** |
| OR-LIB 200-12 | **0.995345** | 0.996342 | 0.999222 | 0.998154 | 0.996344 | 0.998355 |
| Tejada19 214 | 0.215871 | **0.215689** | 0.225567 | 0.328830 | 0.232054 | 0.226860 |
| Tejada19 290 | 0.492610 | 0.492555 | 0.205506 | 0.266447 | 0.148075 | **0.140618** |
| Tejada19 480 | 0.760356 | 0.752216 | 0.314618 | **0.261313** | 0.397477 | 0.275101 |

按主指标：

- OR-LIB 200-1：`indset` 最快，比 RPB 的面积低 19.51%；
- OR-LIB 200-12：所有方法几乎都没有明显进展，SCIP 默认略好；
- Tejada19 214：RPB 最快，最佳公开程序 `setcover` 比 RPB 慢 4.58%；
- Tejada19 290：`indset` 最快，比 RPB 的面积低 71.45%；
- Tejada19 480：`cauctions` 最快，比 RPB 的面积低 65.26%。

每一份公开程序都在相同的三个实例上优于 RPB：OR-LIB 200-1、Tejada19 290 和 Tejada19 480；并在 OR-LIB 200-12、Tejada19 214 上不如 RPB。这说明主要差异来自 UC 实例结构，而不只是事后挑选四份程序中的最好结果。

## 4. 关键收敛过程

### OR-LIB 200-1

- RPB 60 秒内没有把 gap 降到初始值的 90%以下；
- `indset` 在 27.43 秒达到该水平；
- `indset` 的归一化面积比 RPB 低 19.51%。

结论：`indset` 在这一实例上确实收敛更快，不只是最终 gap 更小。

### OR-LIB 200-12

- RPB 与最佳公开程序 `facilities` 的归一化面积分别为 0.996342 和 0.996344，实质上相同；
- 两者都没有在 60 秒内把 gap 降低 10%；
- SCIP 默认的 0.995345 也只具有极小优势。

结论：该实例在 60 秒分支窗口内基本停滞，不能宣称任何策略具有有意义的速度优势。

### Tejada19 214

- `setcover` 在 2.79 秒将 gap 降到初始值的 50%，RPB需要 8.55 秒；
- 但 `setcover` 随后停滞，60 秒内未达到初始 gap 的 10%；
- RPB 在 32.73 秒达到初始 gap 的 10%，并在 56.10 秒证明最优；
- 全过程面积上 RPB 比 `setcover` 好 4.58%。

结论：公开程序早期下降更快，但 RPB 后期收敛更稳，最终 RPB 胜出。

### Tejada19 290

- RPB 在 35.35 秒把 gap 降到初始值的 10%；
- `indset` 只用 11.47 秒；
- `indset` 的全过程面积比 RPB 低 71.45%；
- 但 `indset` 在后期停滞，60 秒时仍未达到 RPB 的最终水平。

结论：`indset` 的早期和总体收敛明显更快，但 RPB 的最后精修能力更强。这是“最终 gap”和“收敛速度”给出不同判断的典型实例。

### Tejada19 480

- RPB 在 48.05 秒把 gap 降到初始值的 50%；
- `cauctions` 在 9.22 秒达到相同相对水平；
- `cauctions` 在 28.96 秒达到 RPB 的 60 秒水平，RPB自身需要 53.48 秒；
- `cauctions` 的全过程面积比 RPB 低 65.26%。

结论：`cauctions` 在该实例上具有明确而稳定的收敛速度优势。

## 5. 与旧“最终 gap”结论的区别

最重要的变化出现在 Tejada19 290：

- 只看60秒最终 gap，RPB更小；
- 看完整60秒轨迹，`indset` 的归一化面积低71.45%；
- 原因是 `indset` 前期下降很快、后期停滞，而 RPB 前期较慢、后期继续精修。

因此，“最终 gap 更小”不能等同于“收敛更快”。用户提出的指标修正是必要的。

## 6. 跨实例探索性汇总

五个实例上的 `mean_gap_ratio` 几何平均为：

| 方法 | 几何平均，越小越好 |
|---|---:|
| SCIP默认 | 0.6035 |
| RPB | 0.6022 |
| setcover | 0.4234 |
| cauctions | 0.4558 |
| facilities | 0.4105 |
| indset | **0.3709** |

这一汇总显示公开程序整体具有较强的早期收敛信号，`indset` 在本批数据上最好。但只有五个实例，不能据此宣布 `indset` 是通用 UC 策略。

## 7. 审计限制

1. 轨迹在每次分支回调和最终状态记录，不是在每一次上下界微小变化时记录。因此积分采用保守的阶梯近似；
2. 外部程序与内部 RPB 的首次分支初始 gap 不完全相同，主指标已通过除以各自 `gap(0)`进行修正；
3. 当前主指标只评价首次分支后的速度，不包含根节点时间；
4. 当前只有五个实例、单次固定种子；
5. 原始结果中的 `gap` 字段可能来自略超过60秒的最终回调，严格比较必须使用 `trajectory_metrics.gap_at_horizon`；
6. 还没有记录连续的上下界事件，若需要精确到每次界改善的时刻，应增加 SCIP 事件级日志。

## 8. 最终判断

本轮能够支持的结论是：

> 公开 LLM4Branch 评分程序在五个代表 UC 实例中的三个实例上，比 RPB 具有更快的分支后收敛速度；在一个实例上 RPB更快，另一个实例所有方法都基本停滞。优势主要体现在早期快速缩小 gap，而 RPB在部分实例上具有更好的后期精修和最优性证明能力。

这为下一步提供了比“最终 gap”更清楚的方向：新的 UC 分支规则应尝试保留公开程序的早期下降能力，同时学习 RPB 的后期精修能力，可能需要按求解阶段切换策略，而不是从头到尾固定使用同一个评分公式。
